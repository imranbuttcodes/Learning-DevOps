# EC2 — Elastic Compute Cloud

**Amazon EC2** stands for **Elastic Compute Cloud**.

At its core:

> **EC2 lets you rent virtual computers (servers) in AWS's data centers and control them remotely.**

Think about the Linux machine you're currently using.

Your ThinkPad has:

```text
CPU
RAM
SSD
Operating System
Network
```

An EC2 instance is essentially another computer with similar components, except the underlying physical hardware belongs to AWS.

```text
Your Laptop                         AWS
┌───────────────┐                 ┌────────────────────┐
│ CPU            │                 │ Physical Servers   │
│ RAM            │                 │       ↓            │
│ SSD            │                 │ Virtualization     │
│ Ubuntu         │                 │       ↓            │
│ Applications   │                 │ EC2 Instance       │
└───────────────┘                 │ Ubuntu / Linux     │
                                  │ CPU + RAM + Storage │
                                  └────────────────────┘
```

You access that EC2 machine remotely.

---

# Why do we need EC2?

Suppose you build your AI backend:

```text
FastAPI
   ↓
Docker
   ↓
AI application
```

It works perfectly on your ThinkPad.

But your laptop isn't a good production server:

* It can turn off.
* Your Internet connection can disappear.
* You don't want to expose your home machine to the Internet.
* Other users need access to your application.
* You may eventually need more CPU/RAM.
* You don't want to maintain physical server hardware.

Instead:

```text
Users
  ↓
Internet
  ↓
AWS
  ↓
EC2
  ↓
Docker
  ↓
FastAPI / AI Backend
```

That's one of the fundamental DevOps use cases for EC2.

---

# What exactly is an EC2 Instance?

You'll hear the word **instance** constantly.

An **EC2 instance** is a virtual machine running on AWS infrastructure.

For example:

```text
EC2 Instance
┌─────────────────────────┐
│ Ubuntu Linux            │
│                         │
│ 2 vCPU                  │
│ 4 GB RAM                │
│ 30 GB EBS storage       │
│ Network interface       │
│                         │
│ Docker                  │
│ FastAPI                 │
└─────────────────────────┘
```

You can SSH into it and work with it much like another Linux computer:

```bash
ssh user@public-ip
```

Then:

```bash
docker ps
docker run ...
```

etc.

This should feel familiar because you've already learned Linux and Docker.

---

# Why is it called "Elastic"?

The **E** in EC2 is important.

**Elastic** means you can adjust computing capacity according to your needs.

Imagine your application normally needs:

```text
2 CPU
4 GB RAM
```

But suddenly traffic increases.

You could use a larger instance:

```text
4 CPU
8 GB RAM
```

That's **vertical scaling**.

Or you could run multiple instances:

```text
        ┌── EC2
Users ──┼── EC2
        └── EC2
```

That's **horizontal scaling**.

Later, AWS services such as **Auto Scaling** can automatically add/remove EC2 instances based on demand.

---

# EC2 isn't just "a VM"

This is an important distinction.

At the basic level:

> **EC2 provides virtual machines.**

But AWS gives you many configurable components around those machines:

```text
                    EC2
                     │
       ┌─────────────┼─────────────┐
       ↓             ↓             ↓
   Instance        Storage       Networking
       │             │             │
    AMI/OS          EBS       Security Group
    Instance Type             Public IP
    Key Pair                  VPC/Subnet
```

We'll learn these one by one.

---

# The 7 EC2 concepts you should understand

For your DevOps goal, focus on these:

### 1. Instance

The actual virtual machine.

```text
EC2 instance = virtual server
```

### 2. AMI

**Amazon Machine Image**

This is essentially a **template/image used to create an EC2 instance**.

For example:

```text
Ubuntu AMI
     ↓
Create EC2 instance
     ↓
Ubuntu server
```

You can think of an AMI somewhat like a **starting blueprint/template for the machine's operating system and configuration**.

---

### 3. Instance Type

Determines the machine's resources.

For example:

```text
Instance Type
     ↓
CPU
RAM
network performance
etc.
```

Different workloads need different instance types.

A small web server doesn't need the same hardware as a massive ML workload.

---

### 4. EBS

**Elastic Block Store**

This is persistent block storage attached to your EC2 instance.

Think:

```text
EC2
 │
 └── EBS Volume
       │
       └── filesystem/files
```

It's conceptually similar to the SSD attached to your computer.

We'll study EBS separately.

---

### 5. Key Pair

Used for securely connecting to an EC2 instance, commonly through **SSH**.

Conceptually:

```text
Your laptop
    │
    │ SSH + private key
    ↓
EC2
```

AWS gives you a key pair consisting of:

```text
Public key  → AWS/EC2
Private key → YOU
```

**Never share your private key.**

---

### 6. Security Group

This controls network traffic to/from the EC2 instance.

For example:

```text
Internet
   │
   │ TCP 22
   ↓
Security Group
   │
   └── EC2
```

You might allow:

```text
SSH     → 22
HTTP    → 80
HTTPS   → 443
```

But you shouldn't blindly open everything.

We'll go deep into security groups when we reach networking/security.

---

### 7. IP Address

Your EC2 instance needs network addressing.

You may encounter:

```text
Private IP
Public IP
Elastic IP
```

For example:

```text
Internet
   ↓
Public IP
   ↓
EC2
   ↓
Private IP
```

We'll connect this to **VPCs and subnets** later.

# Putting everything together

Eventually, you'll launch something resembling:

```text
                    AWS
                     │
                  Region
                     │
                   VPC
                     │
                  Subnet
                     │
             ┌───────┴───────┐
             │                │
          Security         EC2
           Group             │
                             │
                         Ubuntu AMI
                             │
                         Instance
                           Type
                             │
                           EBS
                             │
                          Docker
                             │
                          FastAPI
```

And this is where your previous learning starts connecting:

```text
Linux
  ↓
SSH
  ↓
EC2
  ↓
Docker
  ↓
FastAPI
  ↓
CI/CD
```

That's **exactly** why EC2 is valuable for your DevOps + AI backend path.
